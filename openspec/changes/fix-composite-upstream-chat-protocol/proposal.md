# 集成上游 Chat 协议修复

OpenAI 透传 API Key 账号的能力探测是账号级的。集成上游的 GPT 模型支持 Responses，但同一个 Key 下的 GM 分组只允许 Chat Completions，导致原始 Chat 请求被转换为 Responses 后收到 `403 protocol_not_allowed`。

仅当 API Key 账号启用自动透传、协议覆盖模式为自动、原始请求为 Chat Completions，且收到完整无歧义的协议拒绝时，使用原始 Chat 请求回退一次。保持完整模型 ID、原请求参数、账号级能力标记和原有计时。流式响应开始、请求取消、错误体不完整或包含用量时不重试；手动强制 Responses、认证失败、余额不足和普通权限错误均不适用。

验证先覆盖已探测或未知能力、流式或非流式四种组合，再覆盖非透传账号、手动模式、Responses 形状请求、取消、已提交响应、认证、余额、截断、重复字段和部分输出。

显式提供运行时凭据后，使用候选转发代码直连已配置的集成上游，验证 GPT、CC、GM 的流式与非流式完整回复。不启动生产后台任务，也不连接生产数据库。全部必要真实调用通过后才发布，保留既有模型目录动态发现能力和线上回退版本。

CC 当前是独立的上游余额不足问题。供应商需补足余额或提供可用替代上游，不通过修改余额校验、计费或启用被停用的账号处理。

完整回归另发现模型协议目录用例依赖墙钟生成地址，导致测试目录缓存偶发复用。改为进程序号保证唯一，并在用例结束时清理缓存；修正前重复 50 次失败 17 次，修正后 50 次全部通过。此项仅调整测试隔离，不修改运行时代码。
