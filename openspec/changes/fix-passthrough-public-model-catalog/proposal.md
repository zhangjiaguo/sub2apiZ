# 透传账号公开模型目录修复

## 问题与目标

OpenAI 自动透传账号的账号测试能获取上游完整目录，但公开 `/v1/models` 跳过该账号的映射并回退到本地 GPT 默认目录。集成型上游 Key 因此无法向下游客户端发布 Claude、GLM 及其他自定义模型。

公开目录应动态使用上游 Key 可访问的 OpenAI 兼容模型目录，保留模型 ID 的完整拼写和前缀，不固定账号、供应商、型号或模型数量。

## 实现约束

- 接入现有账号级模型发现服务，复用 60 秒新鲜缓存、后台刷新、5 分钟旧值窗口、凭据隔离及并发请求合并。
- 成功发现目录的透传 API Key 账号不再补入平台默认 GPT 型号；成功的空目录保持为空。
- 发现失败时保留原有本地默认目录回退。普通账号继续发布已有模型映射。
- 保留账号路由白名单、分组白名单和固定分组目录等现有约束，不调整调用模式或计费配置。
- 所有缓存到期后允许上游新增及移除型号自然反映到公开列表。

## 验收

通过真实公开列表处理函数覆盖完整前缀、分组白名单和缓存复用；通过服务回归覆盖自定义型号、上游增删型号、成功空目录、失败回退及普通账号混合目录。线上对比上游目录，确认全部 91 个型号均可获取，并验证 GPT、CC 和 GM 的短文本调用。
